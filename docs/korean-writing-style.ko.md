# 한국어 기술 문서 작성 기준

이 문서는 Mystack의 한국어 문서를 작성하고 검토할 때 적용하는 기준입니다. 영어
문장을 그대로 옮기지 않습니다. 한국어 독자가 필요한 동작, 제한 사항, 다음 행동을
빠르게 찾도록 내용을 다시 구성합니다.

<!-- section: principles -->
## 기본 원칙

- 설명은 `합니다`, 상태는 `입니다`, 제한은 `지원하지 않습니다`로 씁니다.
- 한 문장에는 핵심 주장이나 동작을 하나만 담습니다.
- 한 문단에는 하나의 주제만 담습니다. 긴 문단은 소제목이나 목록으로 나눕니다.
- 중요한 결론과 사용자가 해야 할 일을 먼저 씁니다. 배경과 근거는 그 뒤에 둡니다.
- 영어 문서의 어순을 그대로 따르지 않습니다. 기술적 의미와 출처는 같게 유지합니다.
- 표에는 비교하기 쉬운 짧은 내용만 넣습니다. 긴 제약과 예외는 표 아래에 씁니다.

이 기준은 국립국어원의 [쉬운 공공언어 쓰기 기본
길잡이](https://www.korean.go.kr/common/download.do?c_file_name=d1ce1113-cc07-4f4c-9ea2-dd920eecba7b.pdf&file_path=etcData)와
[Microsoft Learn 기술 콘텐츠 스타일
안내](https://learn.microsoft.com/ko-kr/contribute/content/style-quick-start)를
참고합니다.

<!-- section: terminology -->
## 용어 선택

코드 식별자, API 이름, 설정 키, 오류 코드, 고유 기술명은 원문을 유지하고 백틱으로
표시합니다. 설명에 사용하는 일반 명사는 자연스러운 한국어로 씁니다.

| 피할 표현 | 권장 표현 |
| --- | --- |
| gate | 확인 절차, 판정 기준, 변경 조건, 잠금 |
| gap | 미지원 항목, 남은 차이 |
| shape | 요청 구조, 응답 구조, 데이터 구조 |
| bounded | 상한이 있는, 최대 크기가 정해진 |
| runtime | 실행 환경, 실행 시점 |
| lifecycle | 수명 주기 |
| fixture | 시험 데이터, 시험 환경 |
| runbook | 운영 절차, 작업 절차 |
| payload | 요청 본문, 응답 본문, 전송 데이터 |
| public edge | 공개 API 경계 |
| fail closed | 안전하게 거부 |

실제 필드명이나 안정적인 식별자라면 원문을 바꾸지 않습니다. 처음 나올 때만 한국어
설명을 덧붙입니다.

<!-- section: status -->
## 지원 상태

문서 본문에서는 다음 상태를 사용합니다.

- **검증 완료:** 지정한 클라이언트와 버전으로 공개 API 동작을 확인했습니다.
- **일부 지원:** 핵심 경로는 동작하지만 문서에 적은 제약이 남아 있습니다.
- **미지원:** 요청을 실행하지 않고 명확한 오류로 거부합니다.
- **범위 제외:** 프로젝트 목표가 아니므로 구현하지 않습니다.

프로그램이 읽는 상태값은 기존 영문 값을 유지합니다. 이 값은 백틱으로 표시하고
바로 옆에 뜻을 설명합니다.

<!-- section: structure -->
## 문장과 문단

동작 순서가 중요하면 긴 문장 하나로 이어 쓰지 않습니다. 번호 목록으로 나누고 각
단계의 결과를 분명히 씁니다. 제한 사항은 결론부터 씁니다. 필요한 경우에만 이유와
대안을 덧붙입니다.

AWS 계약과 Mystack 구현을 구분합니다. **AWS 계약**은 공식 AWS 문서나 고정된 SDK
모델이 정의하는 동작입니다. **현재 구현**은 이 저장소에서 시험한 동작입니다. 요청을
인식하거나 Spark SQL이 실행되었다는 사실만으로 AWS와 같은 의미를 보장하지 않습니다.

<!-- section: validation -->
## 검토와 자동 검사

문서를 제출하기 전에 다음 항목을 확인합니다.

- 문장이 존댓말 설명체로 끝나는가?
- 한 문장에 서로 다른 주장이 여러 개 들어 있지 않은가?
- 영어 명사를 나열하거나 영어 어순을 그대로 옮기지 않았는가?
- 설정 키와 코드 식별자를 백틱으로 표시했는가?
- 미지원 기능과 오류 동작을 독자가 찾기 쉽게 설명했는가?
- 영어 문서와 `doc-id`, `section` 표식, 주요 출처 URL이 일치하는가?

마지막으로 `make docs`를 실행합니다. 이 명령은 문서 쌍, 절 순서, 링크, 출처,
한국어 문체를 검사합니다. 자동 문서 검사는 AWS의 [Hexagonal architecture 모범
사례](https://docs.aws.amazon.com/prescriptive-guidance/latest/hexagonal-architectures/best-practices.html)가
권장하는 자동화된 품질 확인 원칙을 따릅니다.
